QA Runbook — Slideshow Automations

Manual QA pass for the automations feature shipped 2026-07-03: recipe (topic → tone → hooks → per-slide directions → images) → generate → schedule → auto-post. Mark each test Pass / Fail / Skip, then Copy results as Markdown at the bottom and paste it back to Claude to get fixes queued.

App: localhost:5175/#app → Automations tab Stack: docker compose up Free path: debug 🐛 → "Mock AI" ON Real path: mockAI OFF (costs below)

TL;DR on cost. One slideshow generation = 1 cheap Gemini text call (~0.1¢) + ~7¢ per AI-generated image slide. Slides that pull from your photo collections are free, and the PIL/FFmpeg composition is local. So: all-collection slideshow ≈ $0.001 · typical 5-slide all-AI (hook + 3 content + CTA) ≈ $0.34 · hybrid (AI hook image, collection content) ≈ $0.14. Posting daily for a month: ~3¢ (collections) to ~$10 (all-AI). Mock mode is $0 everywhere — run this whole runbook free.

Setup (once, ~2 min)

S1Stack up & keys loaded
  1. Run docker compose up (backend :8000, frontend :5175). If backend code changed: docker restart ai-shorts-backend.
  2. Open http://localhost:5175/?debug=true#app and click Automations in the sidebar (below Create).
  3. Backend log should show ⏰ Slideshow automation scheduler started. (docker logs ai-shorts-backend | grep ⏰).

"Slideshow Automations" page loads with a green "New automation" button; scheduler line is in the log.

S2Pick your cost mode
  1. Click 🐛 → Mock AI ON for a $0 run (placeholder images, canned text), OFF to exercise real Gemini (~$0.40 for this whole runbook with one all-AI generation).
  2. The editor's preview column tells you which mode you're in ("Mock mode — placeholder images, no API cost.").

Mode note appears/disappears with the toggle; persists across reloads.

A · Automations list

A1Create an automation
  1. Click New automation.

You land directly in the editor named "New automation", Paused, with 1 empty content slide, a 9:00 AM posting time with all 7 days on, and your browser timezone preselected.

A2List card anatomy
  1. Back out via "← All automations".
  2. Inspect the card: status pill, name, topic line, 3 thumbnail wells, schedule summary ("1×/day · 7/week · 9:00 AM"), TikTok account line.

All present; thumbnails empty until you generate; clicking the name/topic opens the editor.

A3Pause / resume + delete
  1. Click the play icon — pill flips to green "Active". Click pause — back to "Paused".
  2. Click the trash icon → confirm dialog mentions Library items are kept → confirm.

Status flips persist on reload; deleted card disappears; previously generated slideshows still exist in Library.

B · Editor — the recipe

B1Topic, tone & custom tone
  1. Create a fresh automation. Set topic: "how i actually stick to my workout plan (promotes the Evex app)".
  2. Cycle the tone dropdown; pick Custom.

Custom reveals a freeform style-rules textarea; other presets hide it. Save button lights up as soon as anything changes.

B2Hook bank + "Generate 10 more"
  1. Type one hook manually (one line = one hook).
  2. Click Generate 10 more.
  3. Click it again — the new batch should not repeat the first (real mode).

Textarea grows by 10 lines about YOUR topic; unsaved edits are auto-saved before the call; Save resets to disabled after.

B3Slides: directions + add/remove
  1. Slide 2 direction: "showing up consistently, not overdoing it — ~10 words, all lowercase".
  2. Add slide twice; give each a direction; remove one with the ✕.
  3. Toggle CTA end slide on; direction: "soft CTA to track your lifts with the Evex app".

Slides renumber correctly after removal; CTA input only shows when the toggle is on; preview column count updates ("N content slides + CTA").

B4Image source: AI prompt vs Collection
  1. On the hook slide, keep AI image and type a photo prompt.
  2. On slide 2, flip to Collection → "Pick a photo collection…" opens the modal.
  3. In the modal: create a collection ("Gym B-roll"), Add photos (upload 2–3 jpg/png), then click the collection card to pick it.

Modal shows a 4-thumb cover grid + photo count; picked collection's name + count replace the button label; per-slide choice persists after Save + reload.

B5Posting times (the ReelFarm layout)
  1. Change the default time; click day chips off/on (Su–Sa, all on by default).
  2. Add posting time — second row appears (12:00, all days).
  3. Turn 3 days off on one row — the summary line ("2× per day · 11/week") recalculates.
  4. Remove a row with the trash icon. Change the timezone dropdown.

Summary math matches your chips; everything persists after Save + reload.

B6TikTok posting settings
  1. Toggle auto-post on.
  2. If Upload-Post is connected: your TikTok profiles appear in the dropdown — pick one. If not: a hint points to Settings.
  3. Flip Post title between AI prompt ("Title-case the hook") and Static; same for Caption.

Mode toggles swap the placeholder text; all values persist after Save.

C · Generation

C1Generate now — the money shot
  1. Click Generate now (auto-saves dirty edits first).
  2. Mock: ~3s. Real: ~15–60s depending on AI image count.

Preview fills with slide 1 (your hook text over the image, white text + black outline, upper third); ‹ › arrows and dots page through hook → content slides → CTA; each content slide's text follows its direction (incl. casing/length rules); collection slides use YOUR uploaded photos; "Saved to Library." appears.

C2Library + card thumbnails + persistence
  1. Library tab → newest item is kind "Slideshow", status draft, playable MP4, Schedule button works on it.
  2. Automations tab → the card's 3 thumbnail wells now show recent generations.
  3. docker restart ai-shorts-backend, reload — automation, collections, and creations all survive.

Everything persists (SQLite `data/clipzoo.db` + files under `creations/`).

C3Variety across runs
  1. Generate 2–3 more times from the same automation.

Different hooks get picked across runs (random from the bank); collection slides rotate photos instead of always reusing one (with ≥2 photos uploaded); slide text varies in real mode.

D · Scheduler (the "automation" part)

D1A scheduled slot fires once
  1. Set a posting time 2 minutes from now (today's day chip on), Save, set status Active.
  2. Watch docker logs -f ai-shorts-backend.
  3. Note: headless runs use the .env.local GEMINI_API_KEY — a real (non-mock) generation. With an all-collection recipe this is ~0.1¢; with AI images budget ~7¢ each.

At the minute: ⏰ Automation due: <name> exactly ONCE (no double-fire); a new slideshow lands in Library; the card would show last_run_note errors if anything failed. Pause the automation after this test or it posts daily.

D2Auto-post to TikTok (optional — real post!)
  1. Requires UPLOAD_POST_API_KEY in .env.local + auto-post on + a TikTok account picked.
  2. Repeat D1. This publishes a real video to the linked account — use a test account, or Skip this row.

Log shows the post; Calendar tab gains a "posted" entry; creation flips to published. (Not exercised in Claude's QA pass — no test TikTok account.)

E · Edge cases

E1Guard rails
  1. New automation with an empty hook bank → Generate now.
  2. Pick "Collection" on a slide but never choose one → Generate.
  3. Delete an automation that has generated content → check Library.

1: clean error "Automation has no hooks — add at least one hook line". 2: still generates (falls back to a neutral placeholder image — no crash). 3: Library items survive the delete.
