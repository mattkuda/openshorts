Character Slideshows

A new, isolated ClipZoo surface that generates "Gym Made Simple"-style TikTok photo carousels: a recurring cartoon character, huge typeset headlines, your app as the payoff. Local-only for now — the app generates and exports; you post from your iPhone. Decision blocks are at the bottom; pick, add notes, copy back.

TL;DR / Recommendation

Build it as its own tab ("Slideshows"), not a new automation type. It reuses the good parts of the existing machinery (character generation, creations gallery, ZIP export, MP4 concat) but has its own config model, renderer, and DB table — zero changes to automations.py. Text is typeset by PIL, not AI-generated into the image. The character is generated once as a pose pack (~20 PNGs on white) and reused forever, so per-deck image cost is zero and identity never drifts.

Core unit is a Series — character + style preset + niche + CTA config. "Gym tips → EVEX" is Series #1. A second character or a second niche later is just another Series row, which covers your "switch it up" requirement without building anything speculative.

3. Text: typeset, not AI-generated key decision

You asked whether the text is part of the image generation. It could be — Gemini image gen renders legible text now — but I recommend no:

Baked into AI generationPIL typesetting (recommended)
ConsistencyFont/weight/placement drifts every image — the "all over the place" problem you predictedPixel-identical branding across every deck, forever
EditingTypo or weak line ⇒ regenerate the whole image, new driftEdit text, re-composite in <1s (the existing rerender_slides pattern)
Cost1 image call per slide per deck, forever0 after the pose pack exists
Failure modesMisspellings, mangled glyphs, clipped wordsNone — it's a font file

This is also what your reference accounts do — their type is too consistent post-to-post to be generated. AI draws the character; code draws the words. (Formal decision block below in case you want to override.)

5. Pipeline

One-time per character:

Describe character→ Gemini portrait (cartoon, white bg)→ ~20 poses via generate_look()→ You cull bad ones→ Pose pack saved

Per deck (batch of N):

Topic from Series bank (or Gemini fresh)→ 1 LLM call: hook + slide headlines + plug + caption + first comment, accents marked *like this*→ Poses picked from pack (no repeats in a deck)→ PIL composite per slide→ PNG set + MP4 → Creation

Your posting loop: review in gallery → edit any weak line (instant re-render) → ZIP (PNGs + caption.txt) → AirDrop → TikTok Photo Mode on iPhone → trending sound → post.

Renderer details (the new code that matters)

charshow.py — sibling of slideshow.py, no shared state with automations.py:

# STYLE_PRESETS: data-only style definitions
STYLE_PRESETS = {
  "impact": {
    "font": "Anton",            # condensed display; fetched like hooks.py fetches its font
    "casing": "upper", "align": "left",
    "bg": "#FFFFFF", "ink": "#111111", "accent": "#E08A00",  # accent per-Series override
    "char_anchor": "right",     # text column left, character right
    "chrome": ["watermark", "save_badge"],
  },
  "minimal": {
    "font": "Inter-SemiBold", "casing": "sentence", "align": "center",
    "bg": "#FDFDFD", "ink": "#1A1A1A", "accent": "bold",     # accent = bold weight, not color
    "char_anchor": "center_low",
    "chrome": ["swipe_hint"],
  },
}

# Headline engine — the part neither existing renderer has:
# 1. parse *accent* spans from the LLM text
# 2. auto-fit: binary-search font size so wrapped text fills its box
#    (Impact ~60% width beside character; Minimal full-width top third)
# 3. render runs word-by-word, accent words in accent color / bold weight

# Character placement: pose PNG is generated on pure white — pasted
# directly onto the white slide, scaled per anchor. No masking step.

Pose-pack prompt via a new CARTOON_STYLE_SUFFIX in characters.py (parallel to the existing selfie suffix): flat-color comic illustration, thick clean linework, cel shading, full body, isolated on pure white, no text/watermark. Pose list is a fixed bank of ~20 fitness-relevant poses (sprinter start, pointing at abs, dumbbell curl, flexing, arms crossed, shrug, phone-in-hand…), each generated with the portrait as reference image — the mechanism generate_look() already implements.

UI flow (one tab, three zones)

Zone 1 — Series cards. Each card: character thumbnail, style preset, niche, "Generate 1 / Generate batch…" actions, edit. Empty state walks you through character → pose pack → series.

Zone 2 — Batch bar. "Generate N decks" (default 7). Runs with live logs like existing generation flows; mock mode honored for free UI testing.

Zone 3 — Deck grid. Newest decks, slide-strip thumbnails, status chip (Draft / Exported). Click → existing-style editor: slide texts as fields, per-slide pose re-roll, re-render, ZIP download (includes caption.txt with caption + first-comment). Follows STYLE_GUIDE tokens throughout.
