Slideshows, AI Reels, a Format Library & a Hook-Clip Library

How to ship the four features you want without reinventing wheels — grounded in what your codebase already has (which is a lot) and how Crayo, Submagic, Icon, Arcads/Creatify and Revid actually do it. Decisions to lock are selectable at the bottom; pick them and paste the export back to me.

TL;DR. You're further along than it feels. The hard infrastructure already exists: a working Remotion render service (the right engine for slideshows + templated reels), a full AI-UGC pipeline (saasshorts.py: script → AI actor → ElevenLabs VO → Kling talking-head + B-roll), an FFmpeg compositor, a styled subtitle engine (6 fonts, karaoke/pop/word-highlight), and social scheduling.

The thing blocking all four requested features is the same single gap: there is no database. Jobs are in-memory dicts, galleries are read-only S3 listings, all user state is localStorage. "Save your own template," "a hook-clip library," and "what users keep" are impossible to build until there's a persistence + identity layer. That is decision #1 and it gates everything else.

The one mental model that ties it together

Don't build four features. Build one parameterized rendering engine driven by a JSON object — call it a Format — and make all four features configurations of it. This is exactly how Submagic ("a preset is a snapshot of caption style, hook, music, effects") and Crayo ("pre-built viral workflows") model it. A Format says: which engine (clip / slideshow / reel / hook-stitch), which caption style, which hook, which music, which transitions, aspect ratio. Your Remotion compositions already take a props object shaped almost exactly like this.

Proposed architecture — four "engines" all emit/consume one Format object, rendered by the pipeline you already have.

The hook-clip convention (your "girl crying / shocked flight attendant" ask)

These are short (2–4s) emotionally-charged B-roll hook clips shared in "hook packs," dropped in front of a product demo with a text overlay in a native style (white TikTok caption, Snapchat-style, CapCut bold). The viewer is stopped by the emotional clip, the overlay poses the hook, then it hard-cuts to the demo. Tools provide a curated library; power users upload their own. The one thing to get right early: sourcing/licensing those clips (see Feature D + Decision 4).

3 · The four features, each scoped against what you have

A · Slideshow generation

mostly new — engine exists

What it is: a sequence of images/text cards with Ken Burns motion, transitions, captions, AI voiceover and music — the Crayo "fake-text" / listicle / story-slideshow format and the IG photo-dump reel.

What you already have: the entire render+audio stack. Remotion does image sequences trivially (<Series>, <Img>, spring transitions, @remotion/transitions); ElevenLabs VO, the subtitle/caption engine, and music mixing patterns are all present.

What's net-new: a Slideshow.tsx Remotion composition (array of slides → image + per-slide text + duration + transition) and a builder UI (add/reorder slides, per-slide caption, pick transition/voice/music). Optionally an "AI slideshow" mode: Gemini turns a topic/script into slides + image prompts (Flux, which you already call).

Recommendation: Build it as a Remotion composition driven by a slides[] prop — not FFmpeg image2 (harder to do nice transitions/captions). ~1 new comp + 1 modal. Reuse VO + captions verbatim. This is the lowest-effort high-wow feature because the engine is done.
Slide schema + builder mockup 
// remotion/src/compositions/Slideshow.tsx — props
{
  slides: [
    { image: "url|prompt", text: "POV: you found the cheat code",
      durationInSec: 3, kenBurns: "zoom-in", transition: "slide" },
    ...
  ],
  captionStyle: /* reuse Subtitles.tsx style object */,
  voiceUrl: "…", music: "…", aspect: "9:16"
}
Reorderable slide strip + per-slide controls. Render uses the existing Remotion service.

B · AI reel generation

~80% built — needs generalizing

What it is: generate a finished short from a prompt/URL — talking-head UGC, or faceless niche reels (quote/story + B-roll + captions + music).

What you already have: saasshorts.py is a complete reel engine — Gemini script (hook→problem→solution→CTA) → Flux actor → ElevenLabs VO → Kling talking-head + B-roll → FFmpeg composite, premium/low-cost modes, 5 styles. Plus the clip generator's summary-reel + streamer modes.

What's net-new: not much engine — mostly productization. Generalize the saasshorts pipeline from "SaaS URL only" into a reusable reel engine that any Format can call, with a faceless variant (no actor: B-roll/slideshow + VO + captions). Add batch generation (Creatify's "across SKUs") once a DB exists.

Recommendation: Refactor saasshorts.py's stages into composable steps keyed by a Format (which beats: hook-clip? actor? B-roll? slideshow?). Don't build a second pipeline — wrap the one you have. The faceless reel = your slideshow comp + VO + captions, so it falls out of Feature A almost for free.

C · Proven-format library + save-your-own templates

new — blocked on persistence

What it is: two shelves — (1) site-provided "proven formats" you curate (Reddit story, listicle slideshow, talking-head UGC, gameplay split-screen, hook-stitch ad), and (2) user-saved templates ("Save this as a template"), exactly Submagic's preset model.

What you already have: every ingredient a Format references — caption styles, hooks, effects, reframe modes, voices — already exists as parameters. The 5 UGC "styles" prove the instinct; they're just not persisted or reusable.

What's net-new: the Format JSON schema, a library UI (grid of cards with preview + "Use" / "Save as template" / "Duplicate"), a curated seed set authored by you, and — the blocker — a database + identity to store user templates.

Recommendation: Define Format once; make "Save as template" available on every result card (Submagic's exact UX — snapshot the settings that produced this video). Seed 6–8 proven formats yourself so the library is never empty. This is the feature that makes the app feel like a product instead of a tool — but it cannot ship before Decision #1.
Format schema + library mockup 
Format = {
  id, name, engine: "clip" | "slideshow" | "reel" | "hookStitch",
  captionStyle: {...},  // from Subtitles.tsx
  hook: { type: "text"|"clip", style, clipId? },
  music, transitions, aspect, reframeMode,
  owner: userId | "system",   // system = proven format
  isPublic: bool
}
Two shelves: curated "proven formats" (always populated) + user-saved templates (needs a DB).

D · Pre-made MP4 hook-clip library (stitch in front + text overlay)

new — compositing exists

What it is: a browsable library of short viral hook clips (girl crying, shocked flight attendant, jaw-drop reaction, "wait for it"…), each droppable in front of the user's video with a native text overlay (TikTok white caption, Snapchat-style, CapCut bold), then a hard cut to their demo.

What you already have: the compositing/stitching primitives — FFmpeg concat + Remotion <Series>, and a working (animated) text-overlay renderer in HookOverlay.tsx. So "put text on a clip and concat it in front" is mostly assembling parts you own.

What's net-new (3 pieces):

  • The clip library itself — a curated, tagged set of hook MP4s + thumbnails (needs a DB + storage + the licensing decision), plus optional user upload (Icon's "building blocks" model) and optional AI-generated hooks (Veo/Kling, which you already call via fal.ai).
  • Native text-overlay styles — today hooks are a Noto Serif card only. Add TikTok-default, Snapchat, CapCut-bold, typewriter. Note your subtitle engine already has 6 fonts + animations to crib from.
  • The stitch-front assembler — pick hook clip → set overlay text/style/duration → concat before the user's reframed video → render.
Recommendation: Model a hook clip as a Format block (hook:{type:"clip", clipId, overlay:{text,style}}) so it composes with everything else. Ship overlay styles in Remotion (extend HookOverlay.tsx). Decide sourcing first (Decision 4) — a curated/licensed starter pack is the demo-able wedge; user-upload + AI-gen are fast follows.

4 · How to build it — recommended sequence

Ordered to ship something demo-able fast, defer the heavy lift (data layer) only as far as the first feature that truly needs it, and reuse the render engine throughout.

Phase 0~1 wk · unblocks all

Persistence + identity layer

The prerequisite for templates, the hook library, and "what users keep." Recommend Supabase (Postgres + auth + object storage in one) — least new infra, gives you accounts, a formats table, a hook_clips table, and storage buckets to replace ad-hoc S3 listing. Keep S3 if you prefer; the point is a real DB + user IDs. Smallest version: one formats table + anonymous-but-persistent user id, expand later.

Phase 1~1 wk · high wow, low cost

Slideshow engine (Feature A)

New Slideshow.tsx Remotion comp + builder modal, reusing VO + captions. Ships independently of the DB (can start before Phase 0 finishes). Add the AI-slideshow mode (Gemini → slides + Flux images) as a follow-on. This is your fastest visible win.

Phase 2~1–2 wk

Hook-clip library + stitch + native text styles (Feature D)

Seed a curated/licensed starter pack of ~20 hook clips (Decision 4), extend HookOverlay.tsx with TikTok/Snapchat/CapCut styles, build the library picker + concat-front assembler. Add user-upload (Icon's building-blocks model) as a fast follow.

Phase 3~1–2 wk

Format library + save-your-own templates (Feature C)

Define the Format schema, add "Save as template" to every result card, build the two-shelf library UI, and seed 6–8 proven formats. Retrofit the existing engines (clip / slideshow / reel / hook-stitch) to emit & consume Formats.

Phase 4ongoing

Generalize the reel engine + batch (Feature B)

Refactor saasshorts.py into Format-driven composable stages; add a faceless-reel variant (falls out of the slideshow comp) and batch generation. Mostly productization of code you already have.
